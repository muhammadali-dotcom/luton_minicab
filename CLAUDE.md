# Luton Minicab website: notes for Claude

Marketing site for **Luton Minicab** (operated by A2B Radio Cars). Business rules, approved content and open items live in [requirement.md](requirement.md). Read it before changing copy, adding sections or making claims.

## Stack
- Next.js 16.4 (App Router, `src/app`), React 19, TypeScript, Turbopack.
- `next.config.ts` enables `cacheComponents` and `partialPrefetching`. Read the guides in `node_modules/next/dist/docs/` before using Next APIs (see AGENTS.md).
- Tailwind CSS v4 through **`@tailwindcss/postcss`** (`postcss.config.mjs`). Do **not** reintroduce the `@tailwindcss/turbopack` loader. With it, only the first `globals.css` edit after each dev-server start was applied (tested and confirmed).
- Fonts: Inter for body (`--font-inter`), Fraunces for headings (`--font-display`), both via `next/font/google` in `layout.tsx`.
- Icons: `lucide-react`.

## Commands
- `npm run dev`: dev server on port 3000.
- `npm run lint` and `npx tsc --noEmit`: run both after every change.
- `npm run build`: **never run while a dev server is running in this folder.** It rewrites `.next` and has left the dev server serving stale CSS. Either stop the dev server first, or build an isolated copy elsewhere.
- If `LayoutProps` "cannot be found" after clearing `.next`, start the dev server once; it regenerates the types.

## Conventions and gotchas
- The booker is external. Use a plain `<a href={site.bookingUrl}>`, opened in the **same tab** with no `target`. Never build a booking form.
- No `tel:` or `wa.me` links until real numbers are in `site.ts`. `CallToBook` renders an inactive button plus a visible placeholder note while `site.phone` is `null`.
- **Pages open at the top (owner's rule).** `ScrollToTop` in `layout.tsx` scrolls to the top on every path change, except back/forward (the browser restores the position) and links with a `#` section. The `[slug]` pages no longer stream (see Area pages), so there is no loading placeholder: the old `PageFallback` was removed on 23 November 2026, after a Playwright check at 1440 and 375 showed client navigations land at the top with the new h1 and never show the booking banner while loading. Recheck that when adding a dynamic route.
- `cacheComponents` keeps visited pages in the DOM with `display: none`. Selectors like `:has(main…)` will match hidden pages.
- Don't call `new Date()` in server components; it breaks prerendering under `cacheComponents`. The footer shows "© Luton Minicab" with no year for this reason.
- Hooks: avoid `setState` inside effects, which the lint rule `react-hooks/set-state-in-effect` flags. Use `useSyncExternalStore` for browser state, as `HeaderShell` does.
- Accessibility:
  - visible focus (`:focus-visible` uses `--color-ring`)
  - one h1 per page, h2 per section, h3/h4 inside
  - `aria-label`s on icon buttons; decorative SVGs `aria-hidden`
  - tap targets of 44px or more
- **Link labels (owner's rule):** `tel:` links say "Call …", `wa.me` links say "WhatsApp …" (or name the action, e.g. "Update my booking"), and "Contact us", "Talk to our team" and "Ask …" links open `/contact`. Use "Station & Hotel Transfers" as one name everywhere.
- **Fixed fares (owner's policy, November 2026):** the site promises fixed fares. The external booker's "How prices work" text still says the price can follow the distance driven, so the booking-system owner must update the booker and the confirmation email to match (open item in requirement.md).
- **Heading alignment (owner's rule, 17 November 2026):** section headings start on the left by default. Centre only the showcase moments: the homepage hero (`centeredPhoto`) and About hero, the green booking banner (`FinalCta`), the homepage Services cards and the car carousel (`Vehicles`). New sections follow the left default, so a page never switches alignment halfway down.
- Copy: simple British English, short and warm, with no superlatives or unverified claims. See requirement.md.
- **Voice (owner's choice, 18 November 2026):** warm and reassuring. Speak to how people feel on the day (no rush, no worry, someone you can rely on) while staying professional. Avoid stock phrases ("wherever life takes you", "taken care of", "made easy", "at a glance"), stacks of two-part "X. Y." headings, and repeating the "local trips, school runs and airport transfers" list. Reassure only with confirmed facts: no promises such as "never late" or "always on time". Section headings in the shared blocks use `text-balance` so they never leave one word on a line.

## Motion: heading text effect (owner's choice, 19 to 20 November 2026)
- `src/components/ui/text-effect.tsx` is the motion-primitives `TextEffect` (shadcn-style folder; `cn` is in `src/lib/utils.ts`; library `motion`, imported from `motion/react`). Its added `inView` mode keeps the text rendered and replays each time it scrolls into view from above or below (`amount`, default 60% visible), so space is always kept and CLS stays 0. Reduced motion is respected (`MotionConfig reducedMotion="user"`: no movement).
- `SectionHeading.tsx` is every animated heading (slide per word): the section h2s on every page, the green booking banner (`FinalCta`), and, with `as="h1"` and `amount={0.3}`, every page hero h1 in `PageHero` (both branches) and `PickupAreaPage`. It always adds `text-balance`. Use it for new headings.
- **Hydration rule:** the words are split in `ui/split-words.tsx` (`splitWords`, `plainText`), which has no "use client" and runs where the heading's JSX is written. Never split JSX inside a client component: JSX passed from a server component reaches the browser as placeholders but the server render as real elements, so the two trees differ (this caused a hydration error on 20 November 2026). Plain-text and JSX headings (line spans keep their classes) both work. The heading's text from `plainText` (lines joined with a space) is rendered once as a real `<span class="sr-only">` first inside the heading, and the animated word spans stay `aria-hidden` (no `aria-label`, 23 November 2026): screen readers hear it once, and search and AI text extractors, which skip `aria-hidden`, still get every heading. Pixel-identical to before.
- The hero line under the h1 uses `ui/fade-in-view.tsx` (`FadeInView`): fades up 12px, 0.35s after the heading, replaying the same way. Eyebrows, buttons, trust rows, photos and illustrations never animate.
- **Everything else in a section (20 November 2026):** every section component uses `RevealSection` (`ui/reveal-section.tsx`) instead of `<section>`. It walks the section's own JSX where it is written (no "use client", same hydration rule as split-words) and turns blocks into `RevealHost` (`ui/reveal.tsx`): the **same tag with the same props**, so there are no extra boxes and the layout is identical (checked element by element against a plain build). Blocks fade up 16px over 0.5s, replaying in both directions (15% visible). Eyebrows play first; blocks after the heading wait 0.3s; lists and grids (`ul`, `ol`, `dl`, or a `grid`/`flex` class) play their items 80ms apart; a flex row of components (the button rows) fades as one row; `Link` elements animate as links. **Images never animate on their own:** anything holding an element with `src` is kept still and only its other parts animate. The one exception is a **photo card** marked `data-photo-card` (homepage `Services` cards, `AirportCards`, `FleetCards`, `AirportFleet`): it rises 24px as a whole, photo included, 100ms apart, and on hover lifts 6px (`motion-safe:hover:-translate-y-1.5`, with a soft shadow and green border on boxed cards) while its photo zooms to 105% inside a fixed `overflow-hidden` frame (`motion-safe:group-hover:scale-105`, 500ms). Hover uses the CSS `translate` and `scale` properties, so it never fights the motion `transform`. A row holding a component (e.g. `BookOnlineLink` beside a link, `ContactButtons`) or items with their own refs (the `AirportGuide` terminal tabs, whose keyboard focus must keep working) fades as one row; an element with its own text plus decorative spans (the gold-line "OUR SERVICES" label) fades as one piece. Stand-alone pieces a parent can't see inside use `RevealArea` (same walk, any tag): `PopularRoutes`, `DriverHelp`, `AirportArrival`. A section that holds the page h1 is left still; `PickupAreaPage` animates its line (`FadeInView`) and button (`RevealHost`) by hand. `Vehicles` keeps a plain `<section>` (its car stage and controls have their own motion) but its label and intro use `FadeInView`. Use `RevealSection` for new sections; `PageHero` keeps a plain `<section>`. **Keyboard:** a `RevealHost` block shows within 0.15s as soon as anything inside it gets focus (`onFocus`, bubbling), so a tabbed-to link or button is never invisible while its block waits to fade in.
- Not animated: images and illustrations, the top bar, header and footer, hero eyebrows, buttons and trust rows, the `Vehicles` carousel (its own motion), footer link-group headings and the numbered legal-page headings.
- The marker class is `js-text-effect` (not `text-*`: tailwind-merge would drop it). A `<noscript>` style in `layout.tsx` shows the headings and lines without JavaScript.
- `src/components/ui.ts` was renamed `src/components/styles.ts` (the class tokens `container`, `section`, `eyebrow`, `h1`, `h2`, `lead`), so it doesn't clash with the `ui/` folder.
- Measure hero contrast per word (the `span[aria-hidden]` rects), after the animation has ended.
